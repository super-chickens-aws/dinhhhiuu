## Create an Amazon S3 Bucket

Amazon S3 is used to store all audio files generated by Amazon Polly.

Whenever a user converts text into speech, the generated MP3 file will be uploaded to an S3 bucket. The frontend application can then retrieve the file using its URL for playback or download.

Using Amazon S3 provides highly durable, scalable, and cost-effective object storage without requiring any server management.

## Step 3 – Configure the Bucket

Configure the bucket with the following information.

| Setting | Value |
|----------|-------|
| Bucket name | polly-voice-storage |
| AWS Region | Same region as the other AWS resources |
| Object Ownership | ACLs disabled (recommended) |
| Block Public Access | Enable all settings |

The bucket name must be globally unique across Amazon S3.

Blocking all public access ensures that generated audio files cannot be accessed anonymously.

> **Insert screenshot of the bucket configuration.**

---

## Step 4 – Configure Bucket Versioning

Leave **Bucket Versioning** disabled.

Since generated audio files are immutable and can be recreated at any time, versioning is not required for this project.

Versioning can be enabled later if object recovery becomes necessary.

> **Insert screenshot of the Versioning configuration.**

---

## Step 5 – Configure Default Encryption

Under **Default encryption**, select:

| Setting | Value |
|----------|-------|
| Encryption type | Server-side encryption with Amazon S3 managed keys (SSE-S3) |

This ensures that all uploaded audio files are encrypted automatically at rest.

> **Insert screenshot of the Encryption configuration.**

---

## Step 6 – Create the Bucket

Review the configuration.

Click **Create bucket**.

The new bucket now appears in the Amazon S3 bucket list.

## Step 7 – Verify the Bucket

Open the newly created bucket.

Verify that:

- The bucket is empty.
- Public access is blocked.
- Default encryption is enabled.

At this stage, no audio files have been uploaded yet because Amazon Polly has not been integrated.
