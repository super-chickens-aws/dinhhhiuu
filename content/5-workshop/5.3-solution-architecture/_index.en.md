Before creating any AWS resources, we should first understand the overall architecture of the Polly Voice application and how each AWS service interacts within the system.

The application follows a fully serverless architecture, where all infrastructure components are managed by AWS. This approach eliminates the need to provision or maintain virtual servers while providing automatic scalability, high availability, and lower operational costs.

---

## 5.3.1 Overall Architecture

The Polly Voice application consists of three major layers:

- Frontend Layer
- Backend Layer
- Storage Layer

The frontend is hosted on AWS Amplify and provides the user interface.

The backend consists of Amazon API Gateway and AWS Lambda, which process incoming requests and communicate with other AWS services.

Generated speech files are stored in Amazon S3, while application metadata is stored in Amazon DynamoDB.

Authentication is handled by Amazon Cognito before requests are allowed to access the backend services.

## 5.3.2 AWS Services

The Polly Voice application uses several AWS managed services. Each service is responsible for a specific function within the system.

### AWS Amplify

AWS Amplify hosts the React application.

It automatically deploys the frontend from the GitHub repository and provides HTTPS hosting with built-in Continuous Deployment (CI/CD).

---

### Amazon Cognito

Amazon Cognito manages user authentication.

Its responsibilities include:

- User registration
- User login
- JWT token generation
- User session management

Only authenticated users are allowed to access the backend APIs.

---

### Amazon API Gateway

Amazon API Gateway exposes REST APIs for the frontend.

Instead of allowing the frontend to invoke Lambda directly, every request is routed through API Gateway.

API Gateway is also responsible for validating JWT access tokens generated by Amazon Cognito.

---

### AWS Lambda

AWS Lambda contains the business logic of the application.

The Lambda function receives requests from API Gateway and performs several tasks:

- Validate incoming requests
- Call Amazon Polly
- Upload generated audio files to Amazon S3
- Save conversion history into DynamoDB
- Return the response to the frontend

Since Lambda is serverless, compute resources are automatically allocated only when requests are received.

---

### Amazon Polly

Amazon Polly converts text into natural-sounding speech.

The application allows users to select different voices before generating audio.

Amazon Polly returns an audio stream that will later be stored as an MP3 file.

---

### Amazon S3

Amazon S3 stores all generated audio files.

Instead of returning raw audio directly, the backend uploads each MP3 file into S3 and returns its storage location to the frontend.

This approach simplifies file management and allows users to replay or download previously generated audio.

---

### Amazon DynamoDB

Amazon DynamoDB stores metadata for every conversion request.

Typical information includes:

- User ID
- Original text
- Selected voice
- Audio file location
- Creation time

Keeping metadata separate from audio files makes the application easier to query and maintain.

## 5.3.3 Data Flow

The following sequence describes how the system processes a Text-to-Speech request.

### Step 1

The user opens the Polly Voice application hosted on AWS Amplify.

---

### Step 2

The user signs in using Amazon Cognito.

After successful authentication, Cognito returns a JWT access token.

---

### Step 3

The frontend sends a Text-to-Speech request to Amazon API Gateway together with the JWT token.

---

### Step 4

API Gateway validates the JWT token.

If authentication succeeds, the request is forwarded to AWS Lambda.

Otherwise, the request is rejected.

---

### Step 5

AWS Lambda sends the input text to Amazon Polly.

Amazon Polly synthesizes speech and returns an audio stream.

---

### Step 6

Lambda uploads the generated MP3 file into Amazon S3.

---

### Step 7

Lambda stores the conversion history inside Amazon DynamoDB.

---

### Step 8

Lambda returns the generated audio URL together with conversion information to the frontend.

---

### Step 9

The frontend allows the user to:

- Play the generated speech
- Download the MP3 file
- View previous conversion history

## Architecture Advantages

The selected architecture provides several benefits.

### Fully Serverless

No virtual machines or operating systems need to be managed.

AWS automatically provisions compute resources whenever requests arrive.

---

### Secure Authentication

Amazon Cognito authenticates users before backend resources are accessed.

JWT authorization prevents unauthorized API requests.

---

### High Scalability

AWS Lambda automatically scales based on incoming traffic.

Amazon S3 and DynamoDB also scale automatically without manual configuration.

---

### Cost Optimization

Since every core service follows a pay-as-you-go pricing model, the application only incurs costs when users actively use the system.

This architecture is well suited for small and medium-sized cloud-native applications.
